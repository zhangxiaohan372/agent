# 救助规范与流程知识库

> 分类标签：process / rescue / health / material / activity  
> 适用对象：所有志愿者、管理员、社长  
> 来源：校园流浪动物管理系统内部知识库

## 一、发现受伤动物的上报流程

### 1.1 完整上报流程

```
发现疑似受伤/异常动物
        ↓
保持安全距离，不要惊扰动物
        ↓
拍照或视频记录当前状态
        ↓
判断是否紧急（见1.2判断标准）
        ↓
    ┌── 紧急 ──→ 立即联系社团负责人/管理员（电话/微信）
    │                       ↓
    │           管理员确认后安排紧急就医
    │
    └── 非紧急 ──→ 在系统中更新动物健康状态
                        ↓
              将健康状态设置为 attention（需要关注）
                        ↓
              在健康描述中填写异常情况详情
                        ↓
              管理员收到状态变更后安排志愿者跟进
```

### 1.2 紧急 vs. 非紧急判断标准

**以下情况属于【紧急】，需立即电话联系管理员：**
- 动物大量出血或可见骨折/脱臼
- 动物完全无法移动、昏迷或意识不清
- 动物持续抽搐
- 动物被车辆撞击
- 动物疑似中毒（流涎、瞳孔扩大、抽搐同时出现）
- 动物在危险位置（马路中间、水边等）无法自行离开

**以下情况属于【非紧急】，可在系统中更新状态后等待跟进：**
- 动物精神略差、食欲下降但仍能活动
- 轻微的眼鼻分泌物（可能是猫鼻支早期）
- 皮肤轻微脱毛或抓挠频繁
- 轻微跛行但仍能走动

### 1.3 上报时需记录的信息

在系统中更新动物档案时，健康描述字段应包含：
- **发现时间**：具体到日期和时间
- **发现地点**：救助点代码或具体位置描述
- **症状描述**：尽量客观描述观察到的症状
- **照片链接**：上传照片到系统
- **上报人**：填写自己的姓名或学号

**示例格式：**
```
2024-03-15 08:30 发现于MX-01救助点。
症状：右后腿明显跛行，行走时右后腿不敢着地，无明显外伤出血。
精神状态尚可，有食欲，吃了投喂的猫粮。
上报人：李志远（学号202101001）
```

## 二、动物健康状态升级/降级的判断标准

### 2.1 健康状态说明

系统中动物健康状态共有四个级别：

| 状态值 | 显示名称 | 含义 |
|--------|---------|------|
| `normal` | ✅ 健康 | 精神好、食欲正常、无异常症状 |
| `attention` | ⚠️ 需要关注 | 有轻微异常，需要定期观察 |
| `emergency` | 🚨 紧急 | 症状严重，需立即安排就医 |
| `dead` | 💀 已离世 | 动物已死亡 |

### 2.2 升级为 attention（需要关注）的条件

满足以下任意一条即可升级：
- 连续2天食欲下降，进食量不足平时的50%
- 体重明显下降（目测明显消瘦）
- 眼睛有大量分泌物，或出现眯眼、畏光
- 鼻腔有分泌物（流鼻涕），伴或不伴打喷嚏
- 皮肤出现圆形脱毛斑（面积小于手掌）
- 轻微跛行，但仍能正常活动
- 大便不成形超过2天（软便或稀便，无血迹）

### 2.3 升级为 emergency（紧急）的条件

满足以下任意一条需立即升级并安排就医：
- 停止进食超过24小时
- 呕吐超过3次/天，或持续腹泻（水样便/血便）
- 高烧（体温超过39.5°C，触摸耳根或腹部明显发热）
- 明显外伤：大面积伤口、骨折或脱臼迹象
- 大面积脱毛（超过掌心大小，皮肤发红溃烂）
- 精神极度萎靡，无反应或濒死状
- 神经系统症状：抽搐、转圈、失去平衡
- 昏迷或失去意识

### 2.4 降级为 normal（健康）的条件

以下条件**全部满足**后可将状态恢复为正常：
- 食欲完全恢复正常
- 精神状态良好，活动积极
- 症状消失（伤口愈合、皮肤恢复、分泌物消失）
- 如曾就医，须在兽医告知"已康复"后方可降级
- 连续观察3天以上无复发

### 2.5 标记为 dead（已离世）的操作规范

1. 确认动物死亡（有明确证据，如发现遗体）
2. 拍照记录，上传系统
3. 在系统中编辑该动物档案：
   - 健康状态改为 `dead`
   - 勾选"已离世"
   - 填写死亡时间（估计时间）
   - 健康描述中说明死亡情况
4. 遗体处理：联系校园后勤或动物救助机构进行规范处置，不得随意丢弃

## 三、物资申请审核流程

### 3.1 物资需求判断

志愿者在巡查时，发现以下情况应触发物资补充：
- 某救助点某物资库存低于最低库存（系统状态显示"紧缺"）
- 预计一周内将低于最低库存
- 即将举办活动，预计用量增加

### 3.2 物资补充申请流程

```
志愿者发现物资紧缺
        ↓
在系统物资管理页面查看库存详情
（确认是哪个救助点、哪种物资、当前库存数量）
        ↓
在社团群（微信/QQ）中告知管理员：
- 救助点代码
- 物资名称
- 当前库存
- 建议补充数量
        ↓
管理员/社长审核是否批准补充
（考虑社团预算、物资使用频率等）
        ↓
    ┌── 批准 ──→ 管理员安排采购或从库房调配
    │                       ↓
    │           物资到位后，管理员在系统中操作"补充库存"
    │                       ↓
    │           系统自动更新库存数量和状态
    │
    └── 暂不批准 ──→ 管理员说明原因，安排下次补充计划
```

### 3.3 入库操作规范（管理员操作）

在系统"物资管理"模块中点击"补充库存"时，**必须填写**：
- **补充数量**：本次实际入库数量（整数，≥1）
- **操作人**：执行入库操作的管理员姓名
- **备注**：注明来源，例如：
  - `社团采购，2024-03-15，发票号XXXX`
  - `爱心人士捐赠，2024-03-16，大学生创业基金捐赠30kg猫粮`
  - `从明向库房调配至迎西，2024-03-17`

### 3.4 物资出库（消耗）记录

当志愿者从库存中取出物资用于投喂时，需联系管理员记录消耗（当前系统版本以手动更新库存数量为主）：
- 取出数量
- 用途（哪个救助点、哪次活动）
- 操作时间

### 3.5 物资管理注意事项

- **最低库存设置原则**：最低库存 = 当前救助点动物数量 × 每日消耗量 × 7天（即保证至少7天储备）
- **物资有效期**：猫粮/狗粮一旦开封应在30天内用完，每次进库时检查有效期
- **储存要求**：干粮需防潮存放，避免阳光直射；药品需冷藏的放入专用冰箱
- **捐赠物资**：对外接受爱心捐赠的物资，需先入系统登记后才能分发使用

## 四、活动发布与结算规则

### 4.1 活动发布流程

```
活动策划阶段
（确定主题、时间、地点、所需志愿者人数、预计志愿时长）
        ↓
管理员/社长在系统中创建活动
（填写：标题、内容、活动时间、志愿时长）
        ↓
系统将活动状态设为 pending（待发布）
        ↓
社长/管理员审核活动信息无误
        ↓
将活动状态修改为 active（进行中）
        ↓
在公告模块同步发布活动通知
        ↓
志愿者和学生可以开始报名
```

### 4.2 活动状态说明

| 状态 | 含义 | 可操作内容 |
|------|------|-----------|
| `pending` | 待发布 | 仅管理员可见，可继续编辑修改 |
| `active` | 进行中 | 所有用户可见，可报名参与 |
| `completed` | 已结束 | 只读，已完成志愿时长结算 |

### 4.3 活动结算规则

活动结束后，管理员需完成以下操作触发结算：

**操作步骤：**
1. 在系统"志愿活动"模块找到对应活动
2. 点击"编辑"，将活动状态修改为 `completed`
3. 确认"志愿时长"字段的数值（单位：小时）
4. 保存后系统**自动执行**以下操作：
   - 查询所有已报名该活动的用户
   - 为每位参与者累加志愿时长（`volunteerTime += 志愿时长`）
   - 为每位参与者累加活跃度积分（`activeScore += 志愿时长 × 5`）
   - 向每位参与者发送系统通知："活动XXX已结束，您获得了N小时志愿时长和M点活跃度"

**志愿时长计算规则：**
- 志愿时长 = 活动实际持续时间（由管理员填写，单位小时）
- 活跃度积分 = 志愿时长 × 5
- 全勤参与才获得满额时长，中途退出暂不支持部分计算（后续版本迭代）

### 4.4 活动取消与修改规则

- **活动未开始前**（状态为 `pending` 或 `active`）：可直接删除活动，已报名人员的报名记录同步删除，不扣除积分
- **活动进行中取消**：需先联系已报名人员（通过公告通知），再在系统中删除活动
- **活动已结束不可修改志愿时长**：如结算错误，需联系管理员手动修正用户的 `volunteerTime` 字段

### 4.5 活动发布建议规范

| 字段 | 建议填写规范 |
|------|------------|
| 标题 | 简洁明了，20字以内，例如"3月周末明向校区巡查投喂志愿活动" |
| 内容 | 包含：活动目的、集合地点、大致流程、注意事项、联系人 |
| 活动时间 | 填写具体开始时间，例如"2024-03-16 09:00:00" |
| 志愿时长 | 按实际预计时长填写，一般巡查活动2~3小时，救助活动4~6小时 |

### 4.6 特殊活动类型说明

**日常巡查活动（最常见）：**
- 频率：每周1~2次
- 时长：2~3小时
- 主要内容：各救助点投喂、观察动物状态、更新系统档案

**紧急救助活动（不定期）：**
- 触发条件：有动物处于 `emergency` 状态需要就医
- 时长：4~8小时（含送医、等待、接回）
- 参与人数：2~3人即可，人数不宜过多

**专项绝育活动（每学期1~2次）：**
- 提前预约兽医，协调多个救助点动物统一绝育
- 时长：一整天（8小时）
- 志愿时长按实际参与时间计算

**爱心宣传活动（不定期）：**
- 主要内容：在校园内宣传流浪动物救助，招募新志愿者
- 时长：2~4小时

## 五、紧急联系与升级处理

### 5.1 紧急情况处理优先级

1. **人员安全第一**：如果动物具有攻击性，不要冒险接触，先保护自身安全
2. **立即通知管理员**：不要等待，第一时间电话/微信联系
3. **保持现场**：如无危险，留在动物附近等待支援，防止动物离开
4. **记录证据**：在不危及自身安全的前提下拍照/录像

### 5.2 处理升级机制

| 情况 | 初步处理人 | 升级联系人 |
|------|----------|----------|
| 动物状态异常（非紧急） | 发现的志愿者 | 负责该区域的管理员 |
| 动物紧急受伤 | 就近志愿者 | 管理员/社长（电话） |
| 物资严重短缺 | 负责志愿者 | 管理员 |
| 与学校人员产生冲突 | 立即停止争执 | 社长 |
| 发现新动物（未登记） | 拍照记录 | 管理员（系统登记） |
